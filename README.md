# 念念提醒

原生 Android + Go 的个人邮件提醒工具。二次元卡通成长花园：创建任务是播种，真实完成是养分。AI 自然语言建任务，点击、文字或拍照完成，所有完成记录长期保留。服务器持续发送邮件，不依赖手机后台。

## UI 开发入口

完整设计稿统一放在 [UI设计](UI设计/README.md)。后续界面开发先看 [开发规划](UI设计/开发规划.md)，按模块、页面编号找到图片和代码入口；[打开全部 24 张设计画册](UI设计/index.html)。

已发送的邮件记录页取消滚动，草丛固定在屏幕底部作为背景，消息提示与按钮叠在前面；右上树枝下移约 100 像素（当前手机）。仅更新客户端。

## 1.8.3 记录页显示修正

按手机截图修正记录页：右上枝叶延伸到屏幕顶端，底部花草按比例铺满页面宽度，信封使用更清晰的采样并缩小。仅更新客户端，后端不用更新。

## 1.8.2 日历与记录界面

客户端按项目设计图更新日历：庭院横幅、四色月历、日期记录、分页和插画空态；完成记录、邮件详情、凭证照片同步调整。照片加载失败可重试，同月刷新失败保留并标注上次读取的安排。仅更新 Android，沿用现有 1.8.1 后端，实际手机观感待使用验收。

## 1.8.1 念念先帮你安排

念念现在以温和、有主见的小助手身份先给建议。“等会儿搞卫生”“晚点整理桌面”“时间你定”由 AI 根据场景补全时间和间隔，在草稿里用简短的话说明安排，用户核对确认后才真正创建。模糊表达不再作为拒绝原因；模型若先要求补充信息，会携带原句再安排一次。

不能完整表达的复杂规则会给可执行的替代草稿，并明确说明差异；已过期的时间会提出未来方案并说明改动，不悄悄改变日期。仍固定使用 Flash、关闭深度思考。后端升级到 1.8.1 才生效，兼容 1.8.0 客户端；1.8.1 APK 同时调整了输入提示。AI 接口故障或两次均无法产生合法草稿时仍如实报错，不伪造成功。

## 1.8.0 一句话安排与精确时间窗口

AI 固定使用 `deepseek-flash`，关闭深度思考（`thinking.type=disabled`）。先理解事情怎样算完成，再安排首次时间和之后的重复频率：“十分钟后收衣服”表示十分钟后首次提醒，短时生活待办未给重复间隔时默认每 5 分钟继续，完成后停止；“今天下午两点到五点收衣服，收一次就行”表示窗口内完成一次，未给间隔时默认每 30 分钟提醒。补充的间隔会写进草稿提示，可在保存前修改。明确要求“只通知一次，不用确认完成”时优先按一次通知处理。

单次分钟提醒可设置精确截止 `end_at`，截止时刻仍属于窗口，超过后停止提醒、补发和重试；不能同时设置结束日期。窗口已经开始但尚未结束且仍有未来提醒时，可以确认创建；过期窗口不能创建。每天或每周重复的固定小时窗口暂不支持。AI 返回的 JSON 或规则不合规时，最多带着原句和校验原因再问 AI 一次；仍失败会说明失败，不用本地数字正则解析或固定规则兜底。

**客户端和后端需一起升级到 1.8.0。** 旧 APK 在保存规则时会丢失 `end_at`，精确窗口必须使用新版客户端。新版私人后端保留原有内置配置；现有 1.5.0 进程不会因构建新包而自动替换或重启。更新时手动停止旧进程、替换程序，保留原 `data/` 和私人配置，再自行启动，见 `deploy/README.md`。

## 1.7.3 播种页与选花

四种花可以点选，选中项显示浅绿底、描边和圆圈勾。保存后的花种在首页、花园和成长动画中保持一致；未选择的新任务及旧任务继续按原有规则固定分配。选择只保存在这台手机，按账号和规范化服务器地址隔离，不跨手机同步，清除应用数据后会丢失。本次仅更新客户端，后端无需更新。

## 1.6.0 走进自己的花园

花园换成完整的插画庭院，真实植物直接种在草地上，轻点植物就能打开对应的小事。每片花圃最多 12 株，植物多时可以切换花圃或直接跳转，页面明确显示已种总数、各生长阶段数量和当前位置。成长日记收在下方，可展开查看文字和照片。

新增粉色、淡紫色花朵，同一株开花植物在首页和花园保持相同颜色；仅已达到开花阶段的植物使用花朵，不用装饰花冒充你的成果。底部导航图标和文字分别居中，选中时用浅绿色图标底衬。本次为客户端更新，原花园接口即可使用；分钟催办仍需 1.5.0 或更新后端。

## 1.5.0 每隔几分钟催一次

支持“15 分钟后提醒我收衣服，没完成就每隔 5 分钟提醒，直到完成”。AI 草稿和手动创建都能设置首次时间、间隔分钟数；默认不限次数、不设截止日，跨天继续，点完成后永久停止。提前做完也可以直接完成，修改时间或重启不会让已完成任务重新催促。

客户端和后端需一起更新到 1.5.0。提醒仍通过邮件发送，后端每 30 秒检查一次，实际到达还受邮件服务影响；应用无法自动判断衣服是否收好，需要你在任务中点“完成”。重启后只补最近一次，不会把漏掉的多封提醒集中发送。

## 1.4.0 密码与自动登录

注册时验证一次邮箱并设置密码，日常使用邮箱和密码登录。旧账号可在“我的 → 设置密码”验证邮箱后设置首次密码，原任务和记录保留。忘记密码时通过邮箱重设，旧登录会话会失效。

手机默认加密保存账号密码并自动登录；主动退出后会暂停自动登录，账号密码仍可默认填写。保存相同服务器地址保留登录；切换其他地址会尝试用已保存的账号密码登录，失败回首页提示重新登录。不同服务器的账号与数据仍独立，不会自动注册或搬运数据。客户端和后端需一起更新到 1.4.0。

## 1.3.1 生长动画

完成小事后，会依次播放浇水、水滴、养分吸收与植物舒展；1 次发芽、3 次长叶、7 次开花，平时花园里的枝叶轻轻摇摆。可以重看动画，不会重复增加养分。离开页面或进入后台会停止，系统关闭动画时直接显示结果。

客户端和后端需一起更新到 1.3.1，动画才能使用本次完成前后的真实次数。旧后端仍可保存完成记录，客户端会提示更新，不推测植物阶段。

## 1.3.0 成长花园

- 全部主要页面统一暖白、柔绿的卡通风，内置生成的种子、幼芽、枝叶、花朵、浇水壶图标。
- 底部为“今天 / 花园 / 日历 / 我的”。一条提醒对应一株植物，1 次完成发芽、3 次长叶、7 次开花，之后继续累计养分。漏做不清零、不枯萎，已归档的完成记录继续留在花园。
- 花园展示真实全量累计、本周养分、植物列表和最近 12 次完成留念，可回看文字照片。邮件发送次数、打开次数及重复完成提交都不会变成养分。
- **客户端和后端一起更新到 1.3.0。** 旧后端仍可使用原有任务功能，花园会明确提示升级。更新后端需保留原 `data/` 和私人配置，不要同时启动两个后端进程。

## 开始使用

1. 将对应架构的 Linux 发布包上传并解压，运行 `chmod +x niannian && ./niannian`。默认监听 56507。
2. 安装 APK，在初始页面填服务器地址，例如 `http://192.168.1.10:56507`。手机上的 `localhost` 是手机自身；局域网调试要填电脑的局域网 IP。
3. 首次使用邮箱验证码注册并设置密码，已有密码时直接登录。手机加密记住账号密码和登录状态；会话有效时直接使用，过期后尝试自动登录。主动退出会撤销当前会话并暂停自动登录。
4. 点击新建，用一句话描述事情；生成后先看规则摘要，点“调整规则”可展开修改，也可以手动创建。
5. 在任务中点完成，可直接完成或附加文字、拍照/相册图片。“记录”按月显示日历，选择日期查看当天的未来安排、提醒与完成记录，点击查看详情。首页和详情中的开关可启用或暂停提醒。

当前给你的私人发布程序已内置提供的 DeepSeek 与 SMTP 配置，直接运行即可。密钥没有放入 APK 或 Git；本地 `backend/internal/config/defaults/secrets.local.json` 参与编译并被 Git 忽略。发布程序包含私人配置，仅用于自己的服务器。

## 支持哪些提醒

| 场景 | 时间 | 完成规则 |
|---|---|---|
| 公司月度申报 | 每月 1—15 日 09:00 | 本月完成一次就停，下月自动开始 |
| 洗衣服 | 指定一天 09:00、11:00，最多 2 次 | 做完就停，未完成也最多通知 2 次 |
| 收衣服，没做就一直催 | 15 分钟后首次提醒，之后每隔 5 分钟 | 跨天持续，完成一次后永久停止 |
| 下午窗口内收一次衣服 | 今天 14:00—17:00，未给间隔时草稿默认每 30 分钟 | 完成一次或到截止时刻后停止 |
| 每天拉伸 | 每天 20:00 | 每天分别完成，今天完成不影响明天 |
| 一周内办证 | 指定日期范围，每天 09:00 | 范围内完成一次就停 |
| 交材料，未完成一直提醒 | 从今天起每天 20:00，不设截止日 | 完成一次后永久停止 |
| 一次通知 | 指定日期时间 | 通知一次，无需完成 |
| 每周事务 | 选择周一、周五等 | 本周完成一次或每天分别完成 |
| 每隔几天浇花 | 起始日期 + 每隔 N 天 | 按日历日期计算，不随夏令时漂移 |

可设置每天多个时间、结束日期、提醒次数上限、暂停、恢复、稍后提醒和归档。分钟催办间隔为 1—1440 分钟，从首次时间连续计算；跨天不重置，稍后提醒结束后恢复原有节奏。分钟催办还可使用精确截止时间，与结束日期二选一；稍后提醒也不能超过截止。支持 IANA 时区（默认上海），每月 31 日在短月按月末处理。

这是有明确规则的提醒工具，不宣称涵盖所有自然语言。农历、法定节假日、跨月日期窗口、每年重复、每天或每周重复的固定小时窗口等暂不支持；AI 会提示，手动规则也会校验，不会假装已按条件创建。

## 记录与邮件

- SQLite 与媒体默认放在运行目录的 `data/`。不需要安装数据库服务。
- 任务归档不会删除完成记录；编辑任务也保留原来的记录。
- 日历同时展示未来计划和实际记录，按手机时区归入日期。“每隔三天 12:00”创建后即可查看之后各个提醒日，切换月份继续查看。蓝色代表待提醒或仅通知类的已提醒，绿色代表已完成，黄色代表到点未完成，红色代表本期截止后仍未完成；邮件发送结果另行显示。
- 完成后停止本期的规则会移除本期后续计划，下一期仍保留。暂停或归档后不再显示未发送的计划，实际记录和照片保留。点进记录可查看对应任务，已归档任务仍可回看。
- 图片只允许登录的所有者读取；最大 10MB，支持 JPEG、PNG、WebP。
- 邮箱验证码 10 分钟有效，有发送频率与尝试次数限制；无需邮箱白名单，每个账号的数据独立。
- 成功发送的提醒会持久化去重；失败会有限次重试，可在应用中查看发送记录。
- 重启后固定时刻规则只补发当天最近一个有效时间点；分钟催办只补最近一次，可跨午夜，不集中补发过往所有邮件。新建任务不会补发创建前的时间点。
- SMTP 无法与本地数据库进行同一个事务。若服务器在“邮件已被 SMTP 接收，但发送记录尚未落盘”的瞬间断电，重试可能重复一封；普通重启与重复扫描已做去重。
- 拖过一个时间范围仍未完成的任务会标记到期，完成记录不会伪造。通知到达时间也受邮件服务商与收件箱过滤影响。

## 服务器配置

可在程序旁放 `config.local.json`，仅填写要覆盖的字段。参考 `backend/config.example.json`。配置优先级：内置默认 → 本地文件 → `NIANNIAN_*` 环境变量。AI 模型固定为 `deepseek-flash` 且关闭深度思考；旧 `deepseek_model` 字段与 `NIANNIAN_DEEPSEEK_MODEL` 可保留，但不会改变模型。

例如更改监听地址或数据目录：

```json
{
  "addr": ":56507",
  "data_dir": "data"
}
```

配置文件必须是合法 JSON，未知字段会报错。可用 `NIANNIAN_CONFIG` 指定文件路径。环境变量包含 `NIANNIAN_ADDR`、`NIANNIAN_DATA_DIR`、`NIANNIAN_DEEPSEEK_API_KEY`、`NIANNIAN_SMTP_USER`、`NIANNIAN_SMTP_PASSWORD` 等。旧配置中的 `allowed_emails` 和 `NIANNIAN_ALLOWED_EMAILS` 已停用，保留旧配置也不会限制登录。

公网使用建议通过 Caddy/Nginx 的 HTTPS 反向代理访问；应用也允许局域网 HTTP，方便本地与线上切换。不同地址会清除旧页面数据与旧令牌，再用加密保存的账号密码尝试一次登录；验证失败显示首页登录入口。旧连接的返回结果不会进入新页面，已经提交给旧服务器的操作仍可能完成。地址大小写、默认端口和末尾斜杠统一后相同，则保留登录。

长期运行和备份见 `deploy/README.md`。接口约定见 `docs/API.md`。

## 源码构建

后端：Go 1.26 或更高版本，`cd backend && go test ./... && go build ./cmd/server`。纯 Go SQLite，无 CGO；Linux 包包含时区数据。

安卓：Java 17/21、Android SDK 35、Gradle Wrapper。创建 `android/local.properties` 指定 `sdk.dir`，在 `android` 运行 `gradlew.bat --no-daemon assembleDebug`。发布 APK 使用独立签名密钥，升级要保留原签名文件。原文件为 `android/niannian-release.jks`，交付目录另有 `release/niannian-signing-backup.zip`，签名说明见 `android/README.md`；公开源码压缩包不含密钥与签名文件。

`scripts/build.ps1` 构建 Linux amd64/arm64 后端。源代码里没有私人密钥时仍能编译，通过配置文件填入 SMTP/AI 即可运行。

自动测试覆盖时间边界、完成周期、身份隔离、媒体归属、发送去重、持久化和 AI 输出校验。真实手机观感、相机权限及邮箱最终投递由实际使用验收。提醒由邮件触达，应用不请求系统闹钟或通知权限。

DeepSeek 接入依据官方 [JSON 输出](https://api-docs.deepseek.com/guides/json_mode/) 与 [思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)；使用结构化 JSON 草稿，服务端二次验证。
