# 2.6.2 创建提醒追问

普通生活偏好由 AI 主动建议；外部事件的真实日期、时刻缺失，或用户要求先选择时，返回问题。选项适合有限歧义（如时区），具体面试时间可直接输入。候选选项不算用户已经选择。

`POST /api/v1/ai/parse` 保留 `text`，新客户端发送 `supports_clarification: true`。初次不用传补充记录。

待补充响应示例：

```json
{"status":"needs_clarification","reference_time":"2026-10-08T20:00:00+08:00","answered_at":"2026-10-08T20:00:00+08:00","clarification":{"question":"面试按哪个时区？","options":[{"label":"纽约时间","value":"按纽约当地时间"}],"input_hint":"也可以补充完整日期和时刻"}}
```

继续分析时传原始 `text`、最初 `reference_time` 和 `answers` 数组。每项含 `question`、`answer`、`answered_at`；已接受回答的时间取上次响应的 `answered_at`，本轮待提交答案不填该时间，由服务器标记。最多 4 轮，每条回答最多 500 字。最初参考时间超过 7 天、历史时间缺失或顺序错误时返回 400，客户端保留原话并提供重新描述入口。

信息齐全仍返回原有草稿字段；新客户端额外得到 `answered_at`。追问响应没有 `rule`，不进入保存界面。旧客户端没有支持标记时，追问返回 422 和可读问题，不返回空草稿。新版 Android 与 2.6.2 后端配套升级。

原话和每条已接受回答保留各自时间基准，按分析器的 Asia/Shanghai 日历解析相对日期；明确的海外事件仍保留事件时区。当前时间用于判断未来是否还有可执行时间。服务器不保存对话；客户端保存当前编辑会话，受账号、服务器、页面回调隔离保护。失败保留待补充输入，不把失败答案重复加入历史。

后端严格限制追问字段、选项数和长度，草稿与问题互斥。日期范围和工作时段的暂定说明由已验证的最终规则生成，不允许模型在备注承诺未实现的循环。两次模型调用上限不变，明确追问可一次返回；不添加额外模型自评调用。

只分析不创建任务、不发送邮件、不启动调度器。用户确认保存后才走已有创建流程。无手机时仅验证构建、逻辑和真实模型/API；视觉与触控不记为通过。
