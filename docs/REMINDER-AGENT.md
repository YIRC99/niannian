# 2.0.0 提醒与花园实现

## 用户流程

1. 播种页写一句想做的事，念念生成可修改的时间安排。
2. 展开提醒方式，选择通知、日历、闹钟或可选邮件并授予对应权限，保存才正式接管。默认静默 22:00–08:00、最短间隔 5 分钟，可以修改；相同静默起止在客户端转换为空表示关闭静默。
3. 后端 Agent 根据任务、可用渠道、上次执行结果决定下一种方式；执行器限制静默、间隔、完成模式、精确截止和授权。失败、未确认触发或未完成会在本周期内重新判断。只通知一次的规则不改成要求完成。
4. 完成、暂停、延后或归档成功后，本机立刻取消旧计划，再同步新安排。点系统通知可进入对应小事，沿用完成与延后操作。
5. 真实完成赚 3 滴水，浇任何花消耗 1 滴，1/3/7 成长点发芽、长叶、开花。独立种花不收费，已开花不再扣水，四种花可收入图鉴。

## 服务端契约

- `GET/PUT /api/v1/reminders/settings`：开通状态、允许渠道、静默、间隔、时区。只读字段 `configured` 和 `legacy_email_active` 区分老邮件与新执行器。
- `POST /api/v1/reminders/sync`：设备上传能力、执行回执和设备接管/退出动作；返回未来计划完整集合、撤销列表和决策说明。每个账号只有一个当前手机执行端，邮件由服务器执行。
- 计划使用 `channel`、`source`、`reason` 说明方式与依据。`scheduled` 为系统接受排程，`delivered` 为手机报告触发，邮件 `accepted` 为 SMTP 接受；这些都不代表用户已看见。`unconfirmed` 为没有触发回执，不算已收到。日历仅报告写入/排程，不推测系统日历是否弹出。
- `GET /api/v1/garden`：保留真实完成统计，新增 `wallet`、奖励规则和植物 `id/flower_type/growth_count/water_count`。
- `POST /api/v1/garden/plants`：名字、花种及 `request_id`；`POST /api/v1/garden/plants/{id}/water`：`request_id`；两者支持幂等重试。
- 任务创建/修改可带 `flower_type`，与任务事务原子保存；完成返回 `reward`，不自动给对应花浇水。

## 执行边界

AI 决策通过真实模型请求取得并缓存，单轮限制模型调用量；模型不可用时使用有说明的规则保底，不能把保底称为 AI 决策。时间解析仍是原来的 AI 草稿能力，精确截止与完成模式保留。

客户端按账号、服务器及代际隔离数据；旧响应不能恢复退出后的提醒。重启、时间变化和授权变化可恢复/重排。周期同步最短 15 分钟，由 Android 调度；已经下发的计划交系统执行。省电、勿扰、通知通道、厂商日历、强行停止、离线都会影响触发或同步。其他设备上的修改不保证瞬时撤销本机计划。

日历只写入念念自己的本地日历。撤销权限后若无法删除旧事件，保留清理队列并提示恢复权限或手动删除念念日历，不删除用户其他日历。退出手机后撤销本地渠道，显式允许的邮件仍继续。

旧花成长迁移为既有成长，历史已使用的养分不再兑换成水滴。完成奖励、余额与浇水扣款均使用事务和用户隔离；重复提交不重复奖励或扣款。

## 验收分工

开发侧：Go 回归与静态检查、Java 逻辑检查、Release 构建、Lint、签名检查和代码复核。

手机快速检查：登录页与抽屉观感；开通权限后的一次通知/闹钟/日历安排，以及完成后停止；完成小事得水滴并浇另一株花。需要新版客户端和新版后端一起使用。未进行这一轮真机自动化、真实模型线上效果或生产部署验收。
